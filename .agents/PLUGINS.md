## Чим плагін відрізняється від скіла

Скіл — інструкція, як виконати певну роботу. Плагін — пакет, який може містити кілька скілів, інструменти або підключення до сервісу. Тому interfaces є одним плагіном із 15 скілами; їх не потрібно встановлювати ще раз окремо.

Зазвичай пиши бажаний результат: «Знайди цей документ у Drive», «Перевір доступність форми». Агент добере доступні інструменти. Якщо потрібний конкретний пакет, назви його або вибери з меню згадок. У ChatGPT доступний вибір через `@`; у Codex CLI менеджер плагінів відкривається через `/plugins`. Конкретний спосіб вибору в Orca залежить від її інтерфейсу. [Офіційні правила плагінів](https://learn.chatgpt.com/docs/plugins).

Для скілів плагіна у Codex користуйся назвою з меню `$`; для interfaces це, наприклад, `$interfaces:variant`. У Claude Code — `/interfaces:variant`. Коли оболонка не показує плагін або скіл, агент спочатку перевіряє його доступність, а не вдає, що виконав його правила.

Установлений плагін і доступний сервіс — різні речі. Підключення, авторизація та інструменти можуть відрізнятися між Codex і Claude. Папка з файлами Google Drive не переносить твій доступ до Google у другого агента. Назва marketplace після `@` — запис встановлення, а не команда, яку треба вставляти в кожну задачу.

| `variant` | Кілька варіантів одного компонента для порівняння. | `/interfaces:variant Створи 3 варіанти цієї картки` | **Лише явно.** Укажи, що дозволено змінювати. |
| `afk` | Тривала самостійна робота над проєктом на локальній гілці зі звітом. | `/interfaces:afk До 18:00 досліди лише цей розділ…` | **Лише явно.** Це суттєво ширший обсяг за аудит; задавай час, межі й дозволені дії. |

Приклад для Codex, який можна скопіювати:

```text
$interfaces:variant Зроби 3 варіанти картки події догляду для тварини. Збережи погоджений флоу й українські та англійські тексти. Відмінності лише в компонуванні; новий стек не обирай.
```

Скіл `afk` за власним сценарієм може створювати локальну гілку та коміти. Його встановлення не запускає таку роботу й не є дозволом на публікацію, merge або надсилання повідомлень.

`orca-agent-view@inline` у Claude показує стан роботи агента всередині Orca. `orca-opencode-status` виконує подібну службову роль для OpenCode. Їх не потрібно викликати для дизайну чи переносити як звичайний плагін між агентами. Вони не входять до переліку 25 плагінів Codex.

## Повтори та можливі конфлікти

| Набори | Що відбувається | Що робити тобі |
| --- | --- | --- |
| interfaces ↔ impeccable / design-audit / ui-typography / ux-copywriter | Частково покривають ті самі задачі. | Обирати один головний сценарій; інші залучати для конкретної перевірки. [Докладна таблиця](SKILLS.md#перетини-й-суперечності-що-робити). |

| documents ↔ Google Docs | Word-артефакт і нативний документ у Drive — різні результати. | Назвати формат і місце збереження. Не створювати обидва без потреби. |
| spreadsheets ↔ Google Sheets / живий Excel | Файл XLSX, нативна таблиця й підключена сесія Excel мають різні операції. | Назвати конкретний файл/таблицю й бажаний результат. |
| presentations ↔ slides ↔ Google Slides | Перетин презентацій із різними форматами. | Указати HTML, PPTX, Spaces або Google Slides, а також існуючий шаблон. |
| template-creator ↔ openai-templates | Власний шаблон і стандартний набір шаблонів. | Для власного повторюваного формату — template-creator; для разового документа спеціальний запуск шаблонного пакета не потрібний. |
| Notion ↔ Pages ↔ локальні Markdown-файли | Три місця зберігання знань; незалежні копії можуть розійтися. | Вибрати одне основне місце. В інших залишати посилання, якщо дублювання не замовлене. |
| Sites ↔ звичайний реліз репозиторію / Vercel-скіли | Можуть вести до різних способів розгортання. | Назвати конкретний проєкт, середовище й маршрут релізу. Плагін не повинен самостійно переводити cat на інший хостинг. |
| browser ↔ chrome ↔ computer-use ↔ unified-computer-use | Частина можливостей перетинається; це також різні рівні одного механізму. | Зазвичай агент обирає сам. Назвати Chrome, коли потрібна саме твоя вкладка/сесія; для локального тесту — дати URL. |
| Плагін сервісу ↔ GUI того самого сервісу | Те саме завдання іноді можна виконати через підключення або кліки. | Зазвичай достатнє підключення, API чи CLI має перевагу. Відсутній інструмент або авторизацію потрібно назвати прямо. |
| Mobbin ↔ Figma ↔ build-design | Референси, редактор дизайну та перенесення макета в код мають різні ролі. | Не очікувати редагування Figma від самого Mobbin або build-design. Для прямого створення компонентів у Figma потрібний окремий доступний спосіб керування. |

Плагіни на кшталт browser та unified-computer-use можуть бути пов’язаними технічними частинами. Не потрібно видаляти один лише через схожу назву. Аналогічно скіли всередині плагіна не є зайвими окремими встановленнями.

## Для нашої роботи у Figma

Можемо використовувати design-system для специфікації компонентів, impeccable для UI, ux-copywriter і humanizer-uk для текстів, Mobbin для референсів. `interfaces:build-design` корисний на етапі перенесення готового дизайну в код.

У перевіреному переліку плагінів немає окремого Figma-підключення. Наявні скіли не гарантують прямого створення й редагування Figma-компонентів. Перед такою роботою агент перевіряє доступні засоби; поки доступу немає, може допомагати зі специфікацією, параметрами, скриншотами та перевіркою.

## Межі цієї перевірки

Перевірені встановлені файли, призначення й налаштування явного виклику, реєстрації Codex/Claude. Не запускали всі плагіни, кожний сервіс, кожну команду та комбінації скілів. Плагіни під час цього уточнення не вимикали. Окремий скіл bencium-code-conventions вимкнений; проєктні правила добору записані в `.agents/README.md` і підключені з AGENTS.md. Стан підключення може змінюватися; агент повинен перевіряти його під конкретну задачу.
