# cat: правила добору скілів і плагінів

Оновлено 11.11.2026. Ця папка містить адаптовані правила й пам’ятки для дизайн-проєкту cat. Установлені скіли та переносні плагіни залишаються у спільній користувацькій `.agents`; повторно встановлювати їх у проєкт не потрібно.

## З чого почати

- Для користувачки головний вхід — кореневий [README.md](../README.md).
- Для агента — [AGENTS.md](../AGENTS.md); [CLAUDE.md](../CLAUDE.md) імпортує той самий файл для Claude Code.
- Продуктовий контекст і правила репозиторію — у [Codex.md](../Codex.md) саме поточної робочої копії. Не замінюй його брифом з іншої гілки без доручення: у старих копіях може відрізнятися обсяг MVP.
- Прочитай цей короткий README; у [SKILLS.md](SKILLS.md) і [PLUGINS.md](PLUGINS.md) відкривай лише потрібний розділ. Каталог — довідка, а не список для обов’язкового запуску.

## Межі цього проєкту

- Орієнтуйся на погоджені рішення й відкриті питання у Codex.md. Розрізняй рішення засновниці, результати дослідження, гіпотези, макети й реалізацію.
- Пріоритет платформ за брифом — Android, потім iOS та адаптивний веб. Спільні сценарії можна проєктувати разом; системні дозволи, навігацію та сповіщення перевіряй для відповідної платформи.
- Інтерфейс передбачає українську й англійську. Мовні норми, регістр і переноси звіряй окремо для кожної мови. Використовуй словник цього продукту.
- Технологічний стек і візуальна ідентичність ще не зафіксовані в наявному брифі. Наявність HTML-артефактів дослідження не є доказом реалізованого мобільного застосунку.
- daisyUI тут не встановлюємо й не призначаємо як вимогу. Не переносити стек, компоненти або патерни іншого проєкту. React, shadcn, Tailwind чи інший стек не обираються автоматично за вподобанням скіла.
- Імена екранів, персон, компонентів і текстових ключів бери з реєстрів, названих у Codex.md, коли ці реєстри вже існують. Дотримуйся його правил навігатора для нових HTML-сторінок. Не створюй усі майбутні реєстри лише через їхню згадку в брифі.

## Добір інструментів

| Задача | Основний вибір | Межі |
| --- | --- | --- |
| UI/UX або компонент | `impeccable` | Зберігати погоджений сценарій та обсяг; враховувати платформу й поточний рівень готовності дизайну. |
| Дизайн-система, токени, властивості компонентів | `design-system` | Виходити з реєстрів і погодженої візуальної мови; назва скіла не створює компоненти у Figma автоматично. |
| Тексти інтерфейсу | `ux-copywriter` | Використовувати контекст cat, а не термінологію іншого продукту. |
| Мовне редагування українського тексту | `humanizer-uk` | Зберігати зміст дії, умови, числа й терміни; до англійської цей скіл не застосовується. |
| Референси екранів і флоу | Mobbin, якщо доступний і доречний | Референс не доводить попиту або зручності нашого продукту. |
| Загальний аудит UI | Один основний огляд через `impeccable` | Спеціалізовані перевірки додавати під конкретну потребу; видавати один список зауважень. |
| Доступність | `interfaces:better-accessibility`, якщо доступний | Веб-ARIA не замінює перевірку нативної доступності Android/iOS. |
| Готовність до передачі розробнику | `design-handoff-review` | Перевіряти потрібні стани й пояснення поведінки, не лише зовнішній вигляд. |
| Варіанти, стани або перевірка крайніх сценаріїв | Явно відповідний скіл interfaces | `variant`, `state-machine`, `break` потребують явного виклику. |
| Схема для експорту | `diagram-design` | Для інтерактивного пояснення у розмові можна обрати `visualize`. |

Спільні правила пріоритетів і меж доручення застосовуються глобально. `bencium-code-conventions` вимкнений; не відновлюй його. Невирішений суттєвий конфлікт назви конкретно; рутинний добір інструментів виконуй самостійно.

## Як підключаються різні агенти

- Codex читає проєктний AGENTS.md і глобальні інструкції свого середовища; персональні скіли доступні зі спільної `.agents/skills`.
- Claude Code читає CLAUDE.md з імпортом `@AGENTS.md`; персональні скіли підключені через його глобальну `.claude/skills`.
- OpenCode/Copilot та інші агенти використовують підтримувані їхньою версією глобальні й проєктні інструкції. Установлення плагіна в Codex не означає, що його сервіс авторизований в іншому агенті.
- Для явного вибору у Codex використовуй `$`-меню; у Claude — `/назва` або `/плагін:скіл`. Точні приклади є в пам’ятках. Шість ручних скілів interfaces не запускати автоматично.

## Перевірка результату

- Переглянь власний diff і нові файли; збережи попередні та паралельні зміни інших людей/агентів.
- Для текстової задачі перевір зміст і посилання. Для UI — цільовий сценарій, потрібні стани й ширини/платформи. Не вважай клікабельний HTML доказом роботи майбутнього мобільного застосунку.
- Якщо змінювалися залежності, конфігурація або імпорти, звір їх із дорученням і поточним стеком. Не обирай новий фреймворк лише через скіл.
- Публікацію артефакта виконуй лише в межах відповідного доручення. У підсумку назви зроблене, перевірки й неперевірені межі; нове погоджене продуктове рішення зафіксуй у доречному документі.

У цій папці є повні локальні пам’ятки, а не встановлення daisyUI або копії всіх глобальних скілів. Пам’ятки cat адаптовані до цього проєкту; не замінювати їх дослівними інструкціями іншого проєкту під час наступної синхронізації.
